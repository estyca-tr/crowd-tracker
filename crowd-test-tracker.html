How to use

Start on this Cycles list. Each cycle has a Cycle brief / notes for the Applause ask (markets, devices, methods, what we provide). Open a cycle to work on its transactions.

  • Identity (name, role, custom roles) auto-saves locally. Export JSON saves all cycles and transaction data for sharing (does not include Supabase keys). Export to Excel downloads a SharePoint-ready .xlsx backup (live sync stays on Supabase).
  • 🕑 History keeps automatic local snapshots (and one right before anything risky: sync, reset, delete, import) — open it any time to restore an earlier version. Nothing is ever permanently lost.
  • Live sync (optional): open Live sync (Supabase) above, paste your project URL + anon key, connect. Without keys the file stays local-only / Export-Import.

Supabase setup (once): create a free project → SQL Editor → paste:

create table if not exists crowd_tracker (
  id text primary key,
  payload jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);
alter publication supabase_realtime add table crowd_tracker;
-- For MVP shared link (tighten later):
alter table crowd_tracker enable row level security;
create policy "anon read write" on crowd_tracker for all to anon using (true) with check (true);

Then Project Settings → API → copy Project URL and anon public key into Live sync settings. Share HTML + same keys/doc id/access code with Applause.

You are inside a cycle. One row = one transaction. Click a row to open details. + Add transaction opens a draft — close × (or Esc) discards it if you did not enter anything. Use ← All cycles to go back.

  • Set your Display name and Role once in ⚙ Tools & backup (top of page) — it applies everywhere, not per cycle. You can Add role for custom roles and remove them (defaults cannot be deleted). Chat “waiting” badges only appear when the other side sent the last message (by role).
  • 📨 Applause Communication (on the Cycles list, under each cycle card) is a cycle-wide chat — for anything not tied to one transaction (scheduling, coverage, costs). Use the per-transaction Chat tab for case-specific back-and-forth.
  • Whitelisting (in Details) is a fixed list — Need whitelisting / Whitelisted / No need. Set it to Need whitelisting and the tester shows up in the Need whitelisting tile at the top; click that tile to see only those testers.
  • A transaction can have multiple crowd issues and multiple Jira bugs. Approve is a toggle per Jira bug (in the Jira section).
  • Closed rows show a green Approved badge if any Jira bug is approved (or “Approved · N”).
  • Open 🐞 Bug template to set the Jira fields for this cycle's bugs (project, team, type, labels, priority, assignee, fix version, sprint, custom fields, summary format) — with a live preview. Per bug you can override. The cycle name is added as a label automatically. Create bug in Jira opens Jira itself with everything filled in. ⚡ Create in Jira automatically (advanced) fully automates this via the team's Supabase relay — see docs/jira-direct-api-setup.md or docs/jira-automation-setup.md.
  • Identity (name, role, custom roles) auto-saves locally on this browser. Export JSON (⚙ Tools, top of page) saves all transaction data for sharing. Import to load it elsewhere. Live sync: configure Supabase in ⚙ Tools → “Live sync (Supabase)”. Without it, this file saves locally / Export-Import.
